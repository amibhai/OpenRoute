OpenRoute

Detect what's blocking a site — then route only that site around it, at full speed.

✓

A few permissions

Your browser asks you before an extension can do these. OpenRoute never reads page content.

  • Access to all sites — needed to route the blocked ones through a proxy.
  • Encrypted-DNS check (optional) — when a site fails, its domain is checked against your DoH provider to tell DNS tampering from other blocks. Routing works without it.
  • Private windows (optional) — to route there too, open about:addons → OpenRoute → Run in Private Windows → Allow.
1

Turn on Secure DNS

The #1 cause of blocking is DNS tampering, and this is the zero-latency fix. It takes one toggle in your browser and OpenRoute will confirm it worked.

    2

    Browse normally

    When a site fails to load, OpenRoute diagnoses how it's blocked and walks it down a failover ladder automatically:

    • Secure DNS — beats DNS tampering at full speed
    • ECH — beats SNI/DPI filtering where the site supports it
    • Proxy / pool — routes IP-blocked domains through a transport you add
    • Tor — the free fallback when even a proxy IP is blocked
    • Read-only — Wayback / reader view so you can still read the page

    Only blocked domains detour — everything else stays direct and full-speed.

    3

    Want to beat IP blocks & DPI? Add a transport

    For sites blocked at the IP level, OpenRoute needs somewhere unblocked to route through. Point it at a proxy or Tor you already run, or install the companion for built-in Shadowsocks-2022 / VLESS-Reality / Tor and a one-command self-host server.

    An honest word

    No tool is truly unblockable — OpenRoute stacks independent fallback layers so that, in practice, you almost always get through. It's censorship circumvention, not anonymity: for anonymity use Tor Browser. Know your local laws before circumventing restrictions.
