OpenRoute

Detect what's blocking a site — then route only that site around it, at full speed.

1

Turn on Secure DNS

The #1 cause of blocking is DNS tampering, and this is the zero-latency fix. It takes one toggle in Chrome and OpenRoute will confirm it worked.

Set Use secure DNS → Cloudflare (1.1.1.1) or Google.

2

Browse normally

When a site fails to load, OpenRoute diagnoses how it's blocked and walks it down a failover ladder automatically:

  • Secure DNS — beats DNS tampering at full speed
  • ECH — beats SNI/DPI filtering where the site supports it
  • Proxy / pool — routes IP-blocked domains through a transport you add
  • Tor — the free fallback when even a proxy IP is blocked
  • Read-only — Wayback / reader view so you can still read the page

Only blocked domains detour — everything else stays direct and full-speed.

3

Want to beat IP blocks & DPI? Add a transport

For sites blocked at the IP level, OpenRoute needs somewhere unblocked to route through. Point it at a proxy or Tor you already run, or install the companion for built-in Shadowsocks-2022 / VLESS-Reality / Tor and a one-command self-host server.

Popup → Transports. Setup guide: companion/README.md · server/README.md.

An honest word

No tool is truly unblockable — OpenRoute stacks independent fallback layers so that, in practice, you almost always get through. It's censorship circumvention, not anonymity: for anonymity use the Tor rung. Know your local laws before circumventing restrictions.
